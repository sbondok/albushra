
# دليل التشغيل للمبتدئين: محلياً وعلى خادم (Kubernetes)

هذا الدليل مصمم ليأخذ بيدك خطوة بخطوة لتشغيل نظام "تحصيل" سواء على لابتوبك الشخصي أو على خادمك الخاص (Proxmox K8s).

---

## 🏗️ السيناريو 1: التشغيل على جهازك الشخصي (Laptop)

لديك طريقتان لتشغيل النظام محلياً:

### الطريقة الأسهل: باستخدام Node.js مباشرة
إذا كنت تريد التجربة السريعة وتعطيل/تعديل الكود:
1. افتح التيرمينال (Terminal) في مجلد المشروع.
2. قم بتثبيت المكتبات: `npm install`
3. قم بتهيئة قاعدة البيانات: `npx prisma migrate dev`
4. شغل النظام: `npm run dev`
5. افتح المتصفح على: `http://localhost:3000`

### الطريقة الاحترافية: باستخدام Docker (محاكات للخادم)
إذا كنت تريد تشغيله كما سيعمل على الخادم تماماً (معزول):
1. تأكد من تثبيت **Docker Desktop** على جهازك.
2. في مجلد المشروع، أنشأنا لك ملف `docker-compose.yml`. فقط نفذ الأمر:
   ```bash
   docker-compose up --build
   ```
3. انتظر حتى ينتهي البناء وتظهر رسالة "Ready".
4. افتح المتصفح على: `http://localhost:3000`
5. لإيقاف النظام: اضغط `Ctrl+C`.

## 🚀 السيناريو 2: التشغيل على خادم Proxmox (Kubernetes)

بما أن الكلاستر (K8s) موجود على خادم منفصل (Proxmox)، فإنه **لا يستطيع رؤية الصور الموجودة على لابتوبك**. لذلك يجب علينا "رفع" صورة النظام إلى مخزن سحابي (Registry) ثم جعل الخادم يقوم بتحميلها.

### الخطوة 1: تجهيز مخزن الصور (Docker Hub)
1. أنشئ حساباً مجانياً على [hub.docker.com](https://hub.docker.com).
2. سجل الدخول من التيرمينال في لابتوبك:
   ```bash
   docker login
   ```
   (أدخل اسم المستخدم وكلمة المرور).

### الخطوة 2: بناء ورفع الصورة
سنقوم ببناء الصورة وتسميتها باسم المستخدم الخاص بك لرفعها.
*استبدل `your-username` باسم مستخدمك في Docker Hub.*

```bash
# 1. بناء الصورة
docker build -t your-username/albushra-app:v1 .

# 2. رفع الصورة إلى المخزن السحابي
docker push your-username/albushra-app:v1
```

### الخطوة 3: تعديل ملف Kubernetes
1. افتح الملف `k8s/deployment.yaml`.
2. ابحث عن السطر: `image: albushra-app:latest`
3. استبدله باسم صورتك المرفوعة: `image: your-username/albushra-app:v1`
4. احفظ الملف.

### الخطوة 4: النشر على الكلاستر
الآن، اتصل بالـ Master Node في كلاسترك (أو استخدم `kubectl` من جهازك إذا كان متصلاً بالخادم)، ونفذ:

```bash
# 1. تطبيق الإعدادات
kubectl apply -f k8s/deployment.yaml

# 2. التأكد من عمل النظام
kubectl get pods
# (يجب أن تكون الحالة Running)
```

### الخطوة 5: تهيئة المستخدم الأول (Seed)
عند تشغيل النظام لأول مرة على الخادم، يجب إنشاء المستخدم المدير "Admin".
بما أننا نستخدم Docker، يمكننا تنفيذ الأمر داخل الحاوية (Pod) التي تعمل حالياً.

1. احصل على اسم الـ Pod:
   ```bash
   kubectl get pods
   # انسخ الاسم، مثلاً: albushra-fees-system-xxxxx
   ```

2. نفذ أمر الإنشاء داخل الحاوية:
   ```bash
   kubectl exec -it اسم-البود-هنا -- npx tsx prisma/seed.ts
   ```
   *ستظهر رسالة نجاح إنشاء مستخدم admin / admin123.*

---

### كيف أصل للنظام من المتصفح؟
ملف الإعدادات يستخدم `type: LoadBalancer`.
- إذا كان لديك Load Balancer (مثل MetalLB) على Proxmox، ستحصل على **External IP**.
   ```bash
   kubectl get svc albushra-service
   ```
   الرقم الموجود تحت `EXTERNAL-IP` هو رابط النظام.

- إذا **لم** يكن لديك Load Balancer، يمكنك استخدام `NodePort` أو عمل `port-forward` سريع للتجربة:
   ```bash
   # هذا الأمر يربط منفذ جهازك بمنفذ النظام داخل الكلاستر
   kubectl port-forward svc/albushra-service 8080:80
   ```
   الآن افتح في متصفحك: `http://localhost:8080`

## ⚠️ ملاحظة هامة: قاعدة البيانات
النظام حالياً يستخدم **SQLite** (ملف).
- لقد قمنا بإعداد `PersistentVolume` (قرص تخزين دائم) في Kubernetes لكي لا تمسح البيانات عند إعادة تشغيل النظام.
- ومع ذلك، **لا تقم أبداً** بزيادة عدد النسخ (`replicas`) في ملف Deployment عن `1`. لأن SQLite لا يدعم الكتابة من عدة أماكن في نفس الوقت.
- للتوسع مستقبلاً، يجب استبدال SQLite بـ PostgreSQL.
